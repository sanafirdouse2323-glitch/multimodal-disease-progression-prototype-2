# Multimodal Disease Progression Prototype 2

I built this project to experiment with combining different types of health data when looking at changes between patient visits. I am using Python and PyTorch to work with three groups of information: image-derived features, wearable summaries and clinical measurements.

The prototype currently uses data generated by the code itself. I have not connected it to a real medical dataset. My aim at this stage is to work through the data preparation, multimodal model and next-visit prediction pipeline before trying it with real research data.

This repository is separate from my `multimodal-disease-progression-demo` project and from PACA++.

## What the prototype does

The script creates a synthetic group of patients. Each patient has between two and four visits. The time between visits varies, with intervals selected from 3, 6, 9 and 12 months.

For each visit, it generates:

- **Image-derived features:** 8 numerical values. These are simulated features, not measurements extracted from actual scans.
- **Wearable data:** 6 numerical summary values.
- **Clinical data:** 4 values covering scaled age, a binary sex field and two simulated laboratory measurements.
- **Missingness information:** flags show when the image or wearable information is absent. Some clinical values can also be missing.

The model receives 20 input features in total. The four disease-stage labels are numbered 0 to 3. They are generated for this experiment and are not a real clinical staging system.

## How the prediction works

For each patient, I use one visit as the input and the next recorded visit as the prediction target. The model uses the current visit's features to predict the stage recorded at the following visit.

The follow-up intervals are not fixed. For example, the next visit could be three months later for one patient and twelve months later for another. Because of this, the task is **next-observed-visit prediction**. It should not be interpreted as a prediction for a fixed three-, six- or twelve-month horizon.

The network has separate encoders for the image-derived, wearable and clinical feature groups. Their outputs are joined in a fusion layer. There are two prediction heads: one for the next visit's stage and an auxiliary head for the current visit's stage. The next-visit prediction is the main task.

## Data preparation and evaluation

I split the data by patient rather than by visit. This keeps visits from the same synthetic patient in only one of the training, validation or test groups.

Missing values are filled using statistics calculated from the training group. The same training data are used to calculate the feature means and scales. These values are then applied to the validation and test groups.

The held-out test results include accuracy and macro F1. The script also saves the predictions and class probabilities. These results only describe how the code performs on the synthetic data generated for this experiment. They do not show that the model can predict disease progression in real patients.

- `prototype.py` contains the synthetic data generation, preprocessing, PyTorch model, training and evaluation code.

## Set up the project

Python 3.10 or later is recommended.

Clone the repository and create a virtual environment:

```bash
git clone https://github.com/sanafirdouse2323-glitch/multimodal-disease-progression-prototype-2.git
cd multimodal-disease-progression-prototype-2
python -m venv .venv
```

Activate the environment.

**Windows PowerShell**

```powershell
.venv\Scripts\Activate.ps1
```

**macOS or Linux**

```bash
source .venv/bin/activate
```

Install the dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Run the prototype

To run a small experiment and check the training pipeline:

```bash
python prototype.py --patients 40 --epochs 1 --batch-size 16
```

To run the larger synthetic experiment with the default settings:

```bash
python prototype.py --patients 240 --epochs 12 --batch-size 32 --output-dir results
```

The main command-line options are:

| Option | Default | Purpose |
|---|---:|---|
| `--patients` | `240` | Number of synthetic patients to generate |
| `--epochs` | `12` | Number of training epochs |
| `--batch-size` | `32` | Number of examples in each training batch |
| `--learning-rate` | `0.001` | Adam optimizer learning rate |
| `--seed` | `42` | Random seed |
| `--output-dir` | `results` | Folder for the saved outputs |

## Files produced after a run

The output folder contains:

- `metrics.json` — test accuracy, macro F1, split sizes and training history.
- `test_predictions.csv` — target stage, predicted stage and probability for each of the four stages.
- `model.pt` — trained model weights, feature order, training-set preprocessing values, stage labels and run configuration.

The output files are generated when the script is run. They are not included in the repository by default.

## Run the tests

Run the unit tests from the repository folder:

```bash
python -m unittest discover -s tests -v
```

GitHub Actions is configured to install the dependencies, run the tests and execute a small training run when changes are pushed to `main` or a pull request targets `main`.

## What is not included yet

There are several things I still need to work on before this could be used for a real research study:

- The project uses synthetic data only. It does not read real patient records, medical scans or wearable-device files.
- The image branch receives eight simulated numerical features. There is no image-processing or scan-encoding pipeline in this version.
- The stage labels are artificial and have no clinical meaning.
- The target is the next recorded visit, not a clinically defined prediction horizon. Censoring, follow-up patterns and patients who miss visits have not been studied.
- There are no comparisons yet with established unimodal or multimodal baselines.
- Missing-data handling has only been tested in the synthetic generation setup. More complete tests under different missingness assumptions are needed.
- Causal treatment-effect estimation and fairness mitigation are not implemented.
- There is no external validation, clinical assessment, calibration study or clinical explainability evaluation.

I have listed the research scope and further work in [docs/RESEARCH_SCOPE.md](docs/RESEARCH_SCOPE.md).

## Data and clinical use

Please do not add identifiable patient information, medical scans, patient IDs or private cohort files to this public repository. Any work with real health data needs the appropriate permission, ethics approval and secure data handling arrangements.

This is a research and learning prototype. It is not a medical device or a clinical decision-support system. It must not be used to diagnose a condition, recommend treatment or estimate a person's actual prognosis.
