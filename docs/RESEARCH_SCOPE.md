# Research scope and current limitations

## What this version does

This prototype creates a synthetic patient cohort and pairs each visit with the next recorded visit for the same patient. The model receives the current visit's feature values and predicts the stage label assigned to the next observed visit.

The input contains 20 numerical features:

- 8 simulated image-derived values
- 6 simulated wearable summaries
- 4 clinical/tabular values
- 2 missingness indicators

The four stage labels (0-3), patients and measurements are generated by the script. They are not real clinical observations or a recognised disease scale.

The network has separate feed-forward encoders for the three feature groups. Their representations are combined by a fusion layer. The main output predicts the next observed stage; an auxiliary output predicts the current stage during training.

## What the model does not do

The visit intervals are irregular, but the elapsed time between visits is not passed to the model. The model also does not process a sequence of earlier visits. Each example uses one current-visit feature vector to predict the next recorded visit's stage.

For this reason, this version should be described as a synthetic next-observed-visit classification baseline. It is not yet a time-aware longitudinal model and does not predict progression at a fixed future horizon.

## Research directions and implementation status

| Research direction | Implemented in this version | Further work |
|---|---|---|
| Multimodal representation learning | Separate feed-forward encoders for synthetic image-derived, wearable and clinical feature values, followed by feature fusion | Connect authorised imaging and wearable data; compare unimodal and multimodal baselines |
| Longitudinal progression | Current-visit to next-observed-visit stage classification | Add a clinically justified fixed horizon, elapsed-time information, prior-visit history, censoring and follow-up-bias analysis |
| Missing modalities | Synthetic missing values, image/wearable missingness flags, and training-only imputation and scaling | Evaluate MCAR, MAR and MNAR patterns; test complete modality dropout and robustness on real data |
| Evaluation | Patient-level train/validation/test partitions; accuracy and four-label macro F1 on a synthetic held-out set | Add repeated seeds, uncertainty intervals, calibration, class-wise analysis, external validation and appropriate clinical metrics |
| Causal treatment effects | Not implemented | Define a causal question, time ordering, confounding assumptions and sensitivity analyses |
| Fairness and bias | Not implemented | Predefine meaningful subgroups, assess sample sizes and uncertainty, validate externally and evaluate mitigation methods |
| Explainability | Not implemented | Select methods appropriate to the final model and data; assess explanation stability and clinical usefulness rather than relying on visualisations alone |

## Data splitting and preprocessing

Patients, rather than individual visits or visit pairs, are assigned to the training, validation and test partitions. This prevents examples from the same synthetic patient from appearing in more than one partition.

Missing-value imputation values and scaling parameters are fitted using the training partition only. The fitted values are then applied unchanged to validation and test examples.

The held-out test metrics are calculated after model selection using the validation partition. The metric calculation includes all four defined stage labels, including labels that may have no examples in a particular test split. This makes the macro-F1 definition consistent across runs; it does not make the synthetic result clinically meaningful.

## Data and safety

- Do not commit identifiable health data, medical images, patient IDs or private cohort manifests to this public repository.
- Use only authorised datasets in approved research environments with appropriate governance and ethics review.
- The synthetic stage labels are not a clinical scale.
- Synthetic performance is a check of this software experiment only. It is not evidence of diagnostic accuracy or clinical usefulness.
- Before using real data, agree with the relevant research and clinical supervisors on the target definition, time origin, prediction horizon, split strategy, missingness assumptions, baselines and evaluation plan.
- This prototype does not diagnose disease, recommend treatment or estimate an individual's real prognosis.
